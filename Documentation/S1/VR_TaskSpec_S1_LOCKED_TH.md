| บทฝึก | ชุดฝึกกลาง ฝึกทุกกลไกที่ใช้ ไม่สอนคำตอบหรือสั่งกลยุทธ์อ่านก่อน/ตรวจครบก่อน |

**นิยามการล็อก:** ชนิดงาน ตัวเลือก ข้อกำหนดที่เป็นคำตอบ fault เริ่มต้น feedback และสูตรวิเคราะห์หลักไม่เปลี่ยนตามคนหรือผลที่เริ่มเห็น การแก้บั๊ก ตำแหน่งจับ ความชัด การชน และเวลาของ animation ทำได้ก่อนเก็บหลักโดยบันทึกรุ่นและตรวจซ้ำเฉพาะส่วน การพบกฎผิดของจริงต้องแก้แบบเป็นรุ่นใหม่อย่างเปิดเผย ไม่รักษาความผิดเพราะคำว่า locked และไม่รวมข้อมูลคนละรุ่นโดยไม่ระบุ

เวลาสำเร็จ ความยากปานกลาง และปริมาณพฤติกรรมที่จะพบยังต้องตรวจจากคนใช้งานจริง ไม่มีการรับรองว่าทุกคนจะผ่านก่อน 420 วินาทีหรือจะเปิดข้อมูลทุกคน การผ่านก่อน 6 นาทีไม่ใช่ความผิดและไม่เพิ่มงานให้ผู้เข้าร่วมคนนั้น

## 3. ห้องและ UI ร่วม

```
                  [ใบงาน / รหัสสถานี]
 [ข้อมูลอ้างอิง]       [ชิ้นงาน]        [ชิ้นส่วนแยกตามหมวด]
                                           [เครื่องมือ / ถาดพัก]
                   [Inspect] [พัก / ขอความช่วยเหลือ]
```

- ใช้สถานีเดิม ขนาดจริงตามที่ตรวจได้ และพื้นที่เข้าถึงใกล้ตัว ปรับระดับโต๊ะก่อนเริ่มตามวิธีเดียวกันและบันทึกค่า
- ชิ้นใหญ่ เช่น RAM, SSD พร้อมถาด, GPU, ตะแกรง เป็นหน่วยหยิบเดียว รายละเอียดย่อยไม่หลุดตามมือ แยกเฉพาะสิ่งที่ต้องขยับหรือถอดจริง
- ไม่โชว์ชื่อกลุ่ม สาขา H1–H4 คะแนนกลยุทธ์ รายการเงื่อนไขที่ยังผิด หรือเปอร์เซ็นต์เสร็จในหน้าผู้เข้าร่วม
- หน้าเริ่มบอกเวลา 7 นาที; ไม่วางนาฬิกาขนาดใหญ่หรือเสียงเร่งเป็นเกมแข่ง ผู้วิจัยดูนาฬิกาได้
- ข้อมูลเริ่มปิด เปิดเองได้ ไม่บังคับเปิดก่อนหยิบหรือก่อน Pass
- สิ่งที่ระบบช่วย: พื้นที่เลือกที่พอดี การจัดแนวเล็กน้อยเมื่อใกล้และวางทิศที่ถูก การหมุน/เดินเกลียวแบบย่อที่ผู้เข้าร่วมเป็นคนเริ่ม
- สิ่งที่ระบบไม่ช่วย: เลือกชิ้นที่ถูก หมุน RAM กลับด้านโดยอัตโนมัติ ย้ายวัตถุผ่านสิ่งกีดขวาง ต่อสาย/ขันสกรูพร้อมการวาง ซ่อม fault เมื่อถอดชิ้นส่วนอื่น
- ทุกคู่ที่ใส่ได้ทางกลต้องใส่ได้แม้ไม่ตรงข้อกำหนด W2; ถ้า geometry รองรับไม่ได้เพราะตัวระบบยังสร้างไม่ครบให้เป็นปัญหาเทคนิค ไม่บันทึกเป็นความผิดผู้ใช้
- คำว่า ‘ตรวจดู’/Examine อยู่เฉพาะส่วนที่เข้าถึงได้ ให้ข้อมูลจากสถานะจริง ไม่ใช่คำสั่งแก้ ไม่ดูทะลุชิ้นส่วน ไม่อนุมานจาก hover หรือการมองอย่างเดียว
- สีและข้อความแจ้งการจับ/สลักขยับทำได้ แต่ไม่ใช้สีเน้น ‘ชิ้นคำตอบ’ หรือแสดงเฉพาะปุ่มของการกระทำที่ถูก
- ใช้คอนโทรลเลอร์และปุ่มแบบเดียวกันทุกคน ถ้าหัวสายกับชิ้นใหญ่ใช้ท่าจับต่างกันต้องสอนใน Training ก่อน
- เก็บหน้าจอผู้วิจัยและเฉลยออกจากพื้นที่ที่ผู้เข้าร่วมมองเห็น

ใช้ Trainer_FX1 และชิ้นฝึกกลาง ไม่ใช้ RAM/SSD/พัดลมพร้อมเฉลยของงานจริง

| ล็อกและปลด | เข้าใจความต่างระหว่างวางกับยึด และการปลดก่อนดึง |

สอนความหมายของฉลากประเภทหน่วยความจำ ความจุ TBW และกำลังไฟด้วยตัวอย่างกลางสั้น ๆ ได้เหมือนกันทุกคน ไม่เปิดตัวเลข W2 หรือตำแหน่งคำตอบจริงก่อนจับเวลา ไม่มีคำสั่งว่าอ่านก่อนหรือ Inspect ทุกขั้น

เกณฑ์ผ่านคือทำกลไกได้โดยไม่ต้องบอกปุ่มซ้ำ บันทึกเวลาฝึก/จำนวนและเหตุการช่วยเหลือ หากควบคุมไม่ได้หรือไม่สบายให้พัก/ยุติตาม protocol ไม่ใช้การหมดเวลาฝึกเป็นเกณฑ์ว่าพร้อม

## 5. Task A — ประกอบสถานี W2 ให้พร้อมทดสอบบนโต๊ะ

### 5.1 ข้อความที่ผู้เข้าร่วมเห็นเมื่อเริ่ม

> **ประกอบคอมพิวเตอร์สถานี W2**
>
> ประกอบเครื่องจากชุดฐานและชิ้นส่วนที่จัดไว้ให้ตรงข้อกำหนดของสถานี W2 ทั้งหน่วยความจำ หน่วยเก็บข้อมูล และกราฟิก ยึดและเชื่อมต่อให้พร้อม แล้วใช้ Inspect ตรวจผล
>
> ข้อกำหนดสถานี รายละเอียดชิ้นส่วน และวิธีประกอบอยู่ในข้อมูลอ้างอิง คุณเลือกวิธีและลำดับการทำงานเองได้ ไม่จำเป็นต้องใช้ชิ้นส่วนที่จัดไว้ทุกชิ้น
>
> ชุดฐานหยุดทำงานและแยกไฟไว้แล้ว ไม่ต้องถอด CPU, ชุดระบายความร้อน หรือ PSU และไม่ต้องติดตั้งระบบปฏิบัติการ

W2 เป็นรหัสสถานีสมมติ ไม่ใช่รหัสให้ถอดสี/เลข เป้าหมายชัด แต่หน้าจอเริ่มไม่บอก ID ชิ้นคำตอบ ไม่แสดง configuration ที่ถูกให้ทำตาม

### 5.2 ฐานที่เตรียมให้

- เคส ATX จากคลังเดิม บอร์ด DDR4 รุ่นจำลองตาม PRIME B760-PLUS D4 ติดตั้งและยึดแล้ว
- CPU/cooler/CPU_FAN/PSU/24-pin/EPS/front-panel ติดตั้งและเชื่อมพร้อม เป็นฐานที่ระบบตรวจ initial state ได้จริง ไม่ต้องทำในรอบนี้
- แยกไฟไว้ทั้งตอนเริ่มและทุกครั้งที่กลับจาก Inspect ไม่ให้แก้ชิ้นส่วนขณะเครื่องจำลองกำลังทดสอบ
- RAM ว่างทั้งสี่ช่อง; SSD ว่าง; GPU ว่าง ไม่สร้างอาการเสียลับใน A
- ฝาทั้งสองด้านถอดวางพักไว้แล้ว S1 จบที่ **พร้อมทดสอบแบบเปิดเคสบนโต๊ะ** ไม่ต้องปิดฝาหรือจัดสายสวยก่อน Pass
- คงจุดยึด SSD หลังถาดเมนบอร์ดของเคสเดิม ไม่ย้ายให้ทะลุบอร์ด เคสอยู่บนแท่นบริการหมุนแกนตั้งได้เฉพาะเมื่อผู้ใช้จับที่จับฐานและหมุน ไม่หมุนกล้อง/โลกตาม ไม่หมุนให้ผู้ใช้เอง บันทึกการหมุนชิ้นงานแยกจากการเคลื่อนไหวตัวผู้เข้าร่วม
- การหมุนตัวเคสเป็นปฏิสัมพันธ์เพื่อเข้าถึง ไม่ใช่ข้อสอบทักษะใหม่ ต้องลองใน Training; ถ้าจุดเข้าถึง/การชนยังทำไม่ได้ให้เป็น technical blocker ห้ามลบส่วนเคสเพื่อให้ดูผ่าน
- ตำแหน่ง slot ID ต้องตรงทั้ง mesh, scene, manual และ logger
- สาย data หนึ่งเส้นปลายบอร์ดเชื่อมอยู่, สายไฟ SATA และ PCIe ปลาย PSU เชื่อมอยู่ รุ่นสายต้องตรง PSU ต้นทาง ใช้การโค้งแบบกำหนดขอบเขตได้โดยไม่เปลี่ยนข้อมูล pose ดิบ
- สายไฟ GPU ที่ปลายเป็น 6+2 ให้ยึดเป็นหัว 8-pin พร้อมใช้งานสำหรับ S1 ไม่เพิ่มปริศนาประกบ +2 ในรอบนี้

| RAM | รวม 16 GB จาก 2 แผงที่ชนิด/สเปกตรงกัน แผงละ 8 GB; ใช้ชนิดที่บอร์ดรองรับ; ใส่คู่ตำแหน่ง A2/B2 ตามแผนประกอบสถานี | จำนวน/ความจุเป็นข้อกำหนดงานสมมติ; A2/B2 อิงคู่มือบอร์ด |

| GPU | จำนวน 1 ใบ หน่วยความจำกราฟิก ≥8 GB และค่ากำลังไฟของการ์ดที่ระบุ ≤150 W; ใช้ช่องหลักต่อ CPU | ข้อจำกัดสถานีสมมติ ไม่ใช่เพดานกำลังของ PSU ทั้งเครื่อง |
| การประกอบ | ชิ้นส่วนเข้าที่ ยึด และเชื่อมต่อครบ พร้อมทดสอบบนโต๊ะเปิดเคส | เกณฑ์ในสถานการณ์จำลอง ไม่ใช่การตรวจส่งคืนสินค้าจริง |

คำอธิบาย TBW ที่ใช้: ‘ค่าจัดอันดับความทนทานต่อปริมาณการเขียนข้อมูลสะสม ไม่ใช่พื้นที่เก็บไฟล์หรือการรับรองว่าจะเสียทันทีเมื่อถึงค่านั้น’ ไม่ให้คำนวณอายุหรือสูตร DWPD

### 5.4 ตัวเลือกบนโต๊ะ — ตัวเลขทั้งหมดในตารางเป็นสเปกสมมติของ S1

M01/M02 สลับกันระหว่าง A2/B2 ได้ ไม่ล็อก ID ว่าแผงใดต้องช่องใด ทั้งห้าถือเป็นคนละ instance ไม่ใช้ asset ID เดียวแทนทุกแผง สีและ heatspreader ไม่เป็นรหัสคำตอบ

GPU ทั้งสองใช้ mesh ต้นฉบับที่มีขั้ว 8-pin เป็นฐานได้ แต่ฉลาก/metadata ต้องตรงกับตัวเลือกสมมติทั้งคู่ ไม่สร้างความต่างร่อง PCIe ปลอม รุ่น 200 W ไม่ควรขึ้นว่าเครื่องเปิดไม่ได้เพราะเกินนโยบาย 150 W; แยก operational availability กับ station requirement

การใช้ GPU สองใบหัว 8-pin เหมือนกันตั้งใจลดเบาะแสว่า ‘การ์ดใบเดียวที่มีสายให้ต้องถูก’ ตัวใหญ่สุด/VRAM สูงสุดไม่ใช่คำตอบโดยอัตโนมัติ

### 5.5 การจัดวางและตัวเลือกที่เป็นธรรม

- แยกพื้นที่ RAM/SSD/GPU เพื่อให้อ่านค้นได้ แต่ไม่เรียงเป็นลำดับประกอบ ไม่ทำแผ่นรองเป็นภาพเงาของชุดคำตอบ
- แสดงรุ่นและค่าคุณสมบัติจริงของแต่ละตัวเลือกบนฉลาก อ่านใกล้หรือใช้ Examine ขยายได้ ไม่ซ่อนฉลากเพื่อบังคับเปิดคู่มือ
- ไม่ใส่ ‘แนะนำ’, สีเขียว หรือราคาที่ชี้นำคำตอบ
- ตำแหน่งอะไหล่ใช้ layout P/Q ที่กำหนดก่อนทดลอง: Q กลับลำดับซ้าย–ขวาภายในหมวดจาก P; หมวดและระยะไม่เปลี่ยนระหว่างรุ่น ไม่สุ่มสดโดยไม่เก็บ seed
- ใช้ตารางจัดสรรที่ให้ทุกกลุ่มประเทศ/สาขาได้ทั้ง P/Q ใกล้เคียงกัน ไม่ให้ตำแหน่งคำตอบผูกกับประเทศ ไม่ถ่ายโอนฉลากผิด ID

### 5.6 การลงมือและเงื่อนไขทางกายภาพ

```
[เลือก/ติดตั้ง RAM] ─────────────┐
[เลือก/ติดตั้ง SSD + ต่อสาย] ────┼─> [Inspect ตามที่ผู้เข้าร่วมเลือก]
[เลือก/ติดตั้ง GPU + ต่อไฟ] ─────┘
```

ไม่มีลำดับสากล RAM→SSD→GPU ที่บังคับ ทุกลำดับที่ติดตั้งได้จริงยอมรับได้

- RAM: ตรวจชนิด เปิดสลักตามบอร์ด ใส่ร่องให้ตรง กดจนเข้าที่ สลักอาจปิดตามการกดจริงของโมเดล ไม่ต้องกดล็อกซ้ำถ้ากลไกปิดเองได้อยู่แล้ว; half-seat ไม่เป็น connected
- บอร์ดอ้างอิง Q-DIMM มีสลักเคลื่อนด้านเดียวตามภาพคู่มือ 1-12 ห้ามยกกฎ ‘เปิดสองสลัก’ ของ test coupon มาใส่ทุกสล็อตของบอร์ดจริง
- DDR4 ใน A1/B1 หรือ A1/A2 อาจติดตั้ง/ตรวจพบได้ ไม่แกล้งทำให้ boot ไม่ได้; แยกไม่ตรงแผน W2 ออกจาก mechanical invalidity
- SSD: ติดตั้งชุดถาดในตำแหน่งรองรับจริงและขันยึด ต่อ data กับ power แยกกัน สายไม่ต่อให้เองเมื่อวางถาด
- GPU: ใส่ช่องหลัก ยึด bracket และต่อ PCIe power; เปิดโอกาสลองช่องยาวรองที่ใส่ได้จริงด้วยผล requirement mismatch ไม่เด้งจาก socket เพื่อเฉลย
- CPU/base/PSU เป็นขอบเขตเตรียมไว้ ดู/ตรวจได้ ไม่ให้ถอดเพิ่มใน S1 แจ้งขอบเขตตั้งแต่โจทย์ ไม่สร้าง hidden error สำหรับการไม่มี operation ของชิ้นที่ล็อกไว้อยู่แล้ว
- ชิ้นส่วนที่ถูกต้องแต่ทะลุ/ติด collider หรือกฎที่ยังไม่ implement เป็น system issue ไม่ใช่ participant error

### 5.7 เกณฑ์ Pass แบบ state-based

A ผ่านเมื่อครบทุกข้อใน snapshot เดียวขณะ Inspect:
1. ฐานและจุดเชื่อมที่เตรียมไว้ยังอยู่ในสถานะถูกต้อง
2. RAM ที่ติดตั้งมี M01/M02 เท่านั้นใน A2/B2 สลับ ID ได้ ทั้งคู่ seated/latched ตามกลไก รวม16GB
3. SSD S02 หนึ่งชุดเข้าที่ ถาดยึดแล้ว หัวข้อมูลและไฟเชื่อมครบกับต้นทางที่รองรับ
4. GPU G01 หนึ่งใบในช่องหลัก ยึด bracket แล้วและไฟเสริมครบ
5. ไม่มีการเสียบครึ่งทางหรือชิ้นส่วนค้างกีดขวางในพื้นที่ประกอบที่ตรวจได้
6. การทดสอบระบบจำลองและข้อกำหนด W2 ผ่าน โดยไม่ต้องมีการเปิดข้อมูลหรือ Examine เป็นเงื่อนไข

ไม่ต้องปิดฝา/จัดอะไหล่เรียงสวยเพื่อ Pass ของ S1; ไม่ถือว่าทำเสร็จเพราะ ‘เคย’ติดตั้งเมื่อถอดออกแล้ว; RAM/SSD/GPU ที่เกินงานต้องไม่ถูกนับเพิ่มเพื่อชดเชยชิ้นผิด

## 6. Task B — วินิจฉัยเสียงผิดปกติและซ่อมชุดพัดลม

### 6.1 โจทย์ผู้เข้าร่วม

> **ตรวจและซ่อมพัดลม F2 — รายการ B-04**
>
> หลังประกอบกลับ พัดลมมีเสียงสั่นหรือเสียงกระทบผิดปกติ ให้ตรวจหาสาเหตุ แก้ไข และประกอบกลับให้พร้อมใช้งาน แล้วใช้ Inspect ตรวจผล
>
> ตรวจเฉพาะชุดตะแกรง ใบพัด และชุดยึด ไม่ต้องเปิดมอเตอร์หรือวงจรไฟฟ้า ข้อมูลอาการ วิธีตรวจ และวิธีแก้ไขอยู่ในข้อมูลอ้างอิง คุณเลือกจุดตรวจและวิธีทำงานเองได้

เริ่มเครื่องปิดและแยกไฟแล้ว ไม่มี pre-task Inspect Fail อัตโนมัติ รหัส B-04 ระบุอาการไม่ใช่บอกตำแหน่งเสีย ไม่วางอะไหล่คำตอบหรือเครื่องมือที่สื่อว่าจุดเดียวต้องแก้

### 6.2 Initial state และกลไกต้นเหตุ

| ส่วน | Initial state |
|---|---|
| ฐาน/เสา/หัวเครื่อง | ติดตั้งมั่นคง ไม่เป็นส่วนให้รื้อ |
| ตะแกรงหน้า | จัดแนวถูกและคลิปปิด |
| ใบพัด | ชนิดตรงเพลา เข้าร่องเต็ม ตัวล็อกใบพัด tight |
| ตะแกรงหลัง | จัดแนวถูก แต่ตัวล็อกยัง engaged_loose ไม่ clamp แน่น |
| อาการ | ทดสอบจำลองแล้วยังเกิดเสียงผิดปกติจากชุดยึดด้านหลัง |

รูปทรงเริ่มไม่ใช่วงแหวนหาย/คลิปเปิด/แดงเรืองแสง ผู้เข้าร่วมต้องตรวจจึงได้หลักฐาน เงื่อนไขเดียวกันทุกคนไม่มี fault เพิ่มเมื่อใกล้ผ่าน

### 6.3 สามบริเวณตรวจ — ให้หลักฐานไม่ให้คำตอบ

| Target | วิธีตรวจและสิ่งที่เห็น | Initial observation | เงื่อนไขเข้าถึง |
|---|---|---|---|
| B.front_guard | ดู alignment marks และสถานะคลิป; ตรวจการประกบแบบคงแรงทดสอบเชิงภาพ | ประกบตรง คลิปปิด | ภายนอก เข้าถึงได้เมื่อหยุด |
| B.blade_mount | ดูการนั่งบนเพลาและ alignment; ตรวจการขยับชุดใบพัดตาม routine | เข้าร่องเต็ม ชุดยึดไม่ขยับตาม routine | เปิดตะแกรงหน้าแล้ว |
| B.rear_guard_mount | ตรวจการขยับตะแกรงเทียบหัวเครื่อง; เมื่อเปิดถึงตัวล็อก ดูหน้าประกบได้ | มีการขยับใน routine ที่สัมพันธ์กับการไม่ clamp | ตรวจขอบด้านนอกได้; ผิวตัวล็อกด้านหน้าถูกใบพัดบังจนถอดเปิด |

Examine แสดง observation เช่น ‘ขณะทดสอบ ตะแกรงขยับเทียบกับหัวเครื่อง’ ไม่ใช้ ‘เสีย/ผิด/ขันวงแหวนหลัง’ การแสดง movement เป็น **routine ของ simulation** ไม่อ้างว่าเป็นค่าที่วัดจากของจริง ไม่ใส่หน่วยแรงหรือระยะที่ไม่มีแหล่งยืนยัน ระบบตรวจปกติ/ผิดปกติใช้รูปแบบ feedback เดียวกัน

ข้อมูลอ้างอิงอธิบายความสัมพันธ์ปกติ/ผิดปกติครบสามบริเวณและวิธีแก้ ไม่เฉลยว่ารอบจริงอยู่ที่ข้อสาม อาจใช้สามกรณีตัวอย่างในสื่อได้ แต่ไม่เล่นตัวอย่างของ fault จริงเป็นหน้าเริ่มอัตโนมัติ

### 6.4 สิ่งที่ลงมือได้

- ปลด/จัดแนว/ติดตะแกรงหน้าและคลิป
- คลาย/ยึดตัวล็อกใบพัด, ถอด/ใส่ใบพัดตามร่องเพลา
- คลาย/ยึดตัวล็อกตะแกรงหลัง และจัดตะแกรงหลังเมื่อถอดตัวล็อกแล้ว
- Inspect เท่าที่ผู้เข้าร่วมเลือก ไม่มีการบังคับตรวจครบสามจุดและไม่มี minimum retry
- การถอดสิ่งบังไม่คืนค่า rear lock ไป tight; การจับหรือ Examine ไม่แก้สถานะ
- เกลียวแยก absent / engaged_loose / tight; ขณะ engaged ยังมีการรั้งจากเกลียว ไม่แปลว่า loose แล้วดึงทะลุออกได้ทันที
- หมุนในทิศ/แนวที่ถูกแล้วใช้การย่อการหมุนแบบเดียวกับ Training ได้ ไม่ต้องจำลองแรงบิดจริง; ขนาดเกลียวที่ source ระบุ ESTIMATED ยังคงเป็นค่าประมาณ ไม่ยกเป็นแบบมาตรฐาน
- การคลาย/ขันตัวล็อกใบพัดกับ rear ring อาจมีทิศต่างกันตามรุ่นจำลอง ต้องมีเครื่องหมาย/ข้อมูลในสื่อให้ตรวจได้ ไม่ทำทิศลับ; ไม่อ้างว่าแฟนทุกยี่ห้อเหมือนกัน
- หากประกอบทุกจุดใหม่ถูกจริงจนหาย ให้ผ่าน แม้ผู้เข้าร่วมไม่ได้แสดงว่าเข้าใจสาเหตุ; ตีความกระบวนการจาก event และสัมภาษณ์แยกจากผลซ่อม

### 6.5 Pass B

ฐานยังมั่นคง, rear guard จัดแนวและถูก clamp โดย lock tight, blade ถูกชนิด/เข้าร่อง/ยึดด้วย spinner tight, front guard จัดแนวล็อกครบ และ diagnostic routine จำลองไม่พบอาการ ไม่ require การเปิดสื่อ การตรวจครบ หรือคำตอบวินิจฉัยด้วยวาจาก่อน Pass

หากตะแกรงยังเปิดหรือมีชิ้นส่วนไม่พร้อม ระบบไม่จำลองมอเตอร์หมุน การเช็คก่อนทดสอบต้องบอกเหตุ safety-readiness ที่สังเกตได้ ไม่รันใบพัดเปลือยเพื่อสร้างข้อมูล error

|---|---|---|
| A ยังประกอบ/เชื่อมไม่ครบ | ยังไม่ผ่าน: การประกอบหรือการเชื่อมต่อยังไม่ครบ | missing/seated/locked/connected ต่อทุก component |
| A ทุกระบบเชื่อมพร้อมแต่สเปกผิด | ยังไม่ผ่าน: อุปกรณ์ที่ติดตั้งยังไม่ตรงข้อกำหนดสถานี W2 | สเปกจริงและ predicates แต่ละข้อที่ไม่ผ่าน |
| A Pass | ผ่าน: ประกอบเครื่องตรงข้อกำหนดและพร้อมทดสอบ | final state + end reason |
| B ไม่พร้อมทดสอบอย่างปลอดภัย | ยังทดสอบการหมุนไม่ได้: ชุดประกอบป้องกันยังไม่พร้อม | precondition_not_ready + component states |
| B ประกอบพร้อมแต่ยังมีอาการ | ยังไม่ผ่าน: การทดสอบยังพบเสียงผิดปกติ | original_fault_unresolved / user_created_issue ตาม state |
| B Pass | ผ่าน: ชุดประกอบพร้อมและการทดสอบไม่พบอาการเดิม | final state + end reason |
| ระบบประเมิน/สื่อ/การบันทึกขัดข้อง | เกิดข้อขัดข้องของระบบ กรุณาติดต่อผู้วิจัย | SYSTEM_ERROR; ไม่ใช่ Fail ของผู้ใช้ |

คำบอกสถานะทั่วไปยังเป็นข้อมูลที่อาจมีผลต่อกลยุทธ์ จึงคงข้อความ/เวลา/ระดับรายละเอียดระหว่างคน ไม่ให้คลิก Inspect ทำหน้าที่เฉลยชิ้นที่ถูกโดยชื่อ ID ไม่อ่านผล Task B แบบเสียงต่างภาษาไม่เทียบเท่า

## 8. กติกา ‘ไม่เฉลยตั้งแต่เห็น’ และ ‘ไม่ยัดของแล้วผ่าน’

1. ความชัดของวัตถุและปุ่มต้องดี ผู้เข้าร่วมดูออกว่าเป็น RAM/SSD/GPU/พัดลม การไม่เฉลยหมายถึงไม่ชี้ configuration/สาเหตุ ไม่ใช่ทำให้มองไม่ออก
2. ไม่มีวัตถุคำตอบชิ้นเดียวในหมวด A; ไม่มี ID ถูกเรียงกลางทุกหมวดหรืออยู่ชิดช่องเป็นพิเศษ
3. ตัวเลขสูงสุดทุกหมวดไม่ใช่คำตอบ: RAM16แผงเดียวผิดจำนวน, SSD1000ผิดTBW, GPU12GBผิดpower budget
4. เดาถูกหรือใช้ความรู้เดิมทำถูกจริงอนุญาตได้ ตรวจด้วยผลไม่ใช่ ‘เคยเปิดคู่มือ’ ไม่มีทางรับประกันว่าผู้เชี่ยวชาญทุกคนต้องสับสน
5. สเปก W2 มีเฉพาะในการเปิดข้อมูลอ้างอิง แต่ทุกคนรู้ว่ามีและเปิดได้ อิสระที่วัดคือจะเข้าถึงเมื่อใด/แบบใดเทียบกับลงมือ ไม่อ้างว่าสถานการณ์นี้วัดนิสัยหาข้อมูลถาวร
6. ไม่ require เปิดทุกสื่อ ไม่ซ่อนข้อมูลสำคัญคนละสื่อ ไม่สุ่มเปลี่ยนคำตอบระหว่างเล่น
7. วัตถุที่ตกใกล้ socket ไม่ถูกติดตั้งเอง การเริ่ม attempt ต้องมาจากปฏิสัมพันธ์โดยตั้งใจ; ไม่ใช้ OnTriggerEnter อย่างเดียวตัดสิน
8. ผิดสเปกแต่ fit ได้ต้องนั่งลง socket ได้ ไฟฟ้า/ความเข้ากันได้กับงานประเมินแยก ไม่บิดฟิสิกส์ให้เกิดข้อสอบง่าย
9. ไม่มี checklist progression ที่จำว่า ‘เคยทำครบ’ ถ้าถอดออกแล้วสถานะต้องกลับทันที
10. feedback ที่เป็นการจับ/การชน/การขันทำได้ตามเหตุ ไม่เปลี่ยนเป็น hint หรือซ่อมโดยระบบ
11. ต้นทุนการ Inspect ไม่เพิ่มหลัง Fail ไม่มี penalty เวลาเทียม ไม่มีจำกัด retries เพื่อให้เกิดพฤติกรรมตามที่ต้องการ

## 9. งบเวลาและเพดาน

งบต่อไปนี้เป็น **สมมติฐานออกแบบ** ไม่ใช่สถิติหรือเวลาเทสต์ที่พบแล้ว

| ช่วง A | วินาที | ช่วง B | วินาที |
|---|---:|---|---:|
| รับโจทย์/อ่าน/เปรียบเทียบ | 90 | รับโจทย์/อ่าน/ตรวจรอบนอก | 90 |
| ติดตั้ง RAM สองแผง | 50 | เปิดเข้าถึงและตรวจชุดใบพัด | 65 |
| ติดตั้ง SSD/ยึด/ต่อสองสาย | 65 | ตีความและตรวจจุดยึด | 45 |
| GPU/ยึด/ต่อไฟ | 55 | แก้และประกอบกลับ | 70 |
| ตรวจความครบ/Inspect | 40 | ตรวจความครบ/Inspect | 30 |
| ฐานเมื่อทำราบรื่น | 300 | ฐานเมื่อทำราบรื่น | 300 |
| เผื่อทบทวน/ลองใหม่ | 120 | เผื่อทบทวน/ลองใหม่ | 120 |
| เพดาน | 420 | เพดาน | 420 |

เวลาต้องรวมการเปิดข้อมูล การรอเล่นสื่อ การหมุนชิ้นงานและผล Inspect ปกติ ใช้ `wall_elapsed_s` ตาม start/end ควบคู่กับ `active_elapsed_s` ที่หักเฉพาะพัก/เทคนิคอย่างเป็นทางการ ห้ามหักเวลาการคิดหรือการอ่านให้ดูเร็ว

จบเมื่อ Pass แสดงสำเร็จก่อนเพดาน, หมดเวลาที่ 420, ถอนตัว, safety stop หรือ technical failure เก็บ end_reason คนหมดเวลาไม่เท่ากับทำสำเร็จใน 420 วินาที ไม่ต่อเวลาเฉพาะคนที่ใกล้ผ่าน ไม่ตั้ง Pass ถ้าเพียงวางชิ้นสุดท้ายแล้วไม่ได้ตรวจ

Task start คือหลังอ่านคำแนะนำทั่วไป/พร้อมแล้ว เมื่อเปิดโจทย์เฉพาะสถานีพร้อมการเข้าถึงข้อมูลและวัตถุจริง สื่อเฉพาะงานยังดูไม่ได้ก่อน TASK_STARTED

## 10. นิยามเหตุการณ์ — เก็บความหมาย ไม่ใช่จำนวนคลิก

ใช้ HandsLabLogger เดิมผ่าน ResearchFlow/ResearchTaskPort และตัวปรับ task ไม่สร้าง writer คู่ขนาน ไม่ใช้ event จาก QA scene เป็นข้อมูลผู้เข้าร่วม

| Event | ความหมาย |
|---|---|
| TASK_STARTED / TASK_ENDED | เวลาเริ่ม/เหตุจบ พร้อม complete initial/final snapshot |
| INFORMATION_OPEN / INFORMATION_CLOSE | ข้อมูลอ้างอิงแสดง/หายจริง พร้อม format, content_id, section_id, language, exposure_id |
| INFORMATION_SECTION_VISIBLE / MEDIA_* | หน้า/หัวข้อที่แสดงจริง หรือ playback/seek ที่ทำจริง ไม่ถือว่าอ่านเข้าใจ |
| GRAB / RELEASE / WORKPIECE_ROTATE | จับ/ปล่อย/หมุนชิ้นงาน ไม่เหมารวมว่าเป็น repair |
| EXAMINE | การตรวจโดยตั้งใจ มี target, observation_id, access_state, snapshot; ดูเฉย ๆ ไม่แก้สถานะ |
| ACTION | มี action_type เช่น INSTALL, REMOVE, CONNECT, DISCONNECT, FASTEN, UNFASTEN, ALIGN |
| REPAIR | ใช้เฉพาะ corrective operations ของ B ตามรายการที่กำหนด ไม่ตั้งทุก action ใน A เป็น REPAIR |
| INSPECT | การร้องขอและ snapshot ก่อนตรวจ |
| INSPECT_PASS / INSPECT_FAIL | ผลประเมิน พร้อม inspection_id และ result kind |
| INSPECT_FEEDBACK_VISIBLE | เวลา/ข้อความ feedback ที่ผู้เข้าร่วมได้รับจริง; จุดเริ่ม H4 |
| SYSTEM_* | tracking, recovery, pause, error, automatic animation; ไม่ใช้เป็นการตัดสินใจผู้เข้าร่วม |

A: INSTALL/CONNECT/FASTEN และความพยายามที่ถูกปฏิเสธเป็น assembly operations; การจับเพื่อมอง/Examine/หมุนเคสไม่ใช่ assembly attempt

B: เปิด/ถอดตะแกรงหน้าและถอดใบพัดเพื่อเปิดทางเป็น ACCESS; การจัดตะแกรงกลับ/ยึด/ปรับชุดยึด/ใส่ใบพัดกลับเป็น corrective operation ตามกฎที่กำหนด ห้ามอนุมาน intention ว่าเขารู้ fault จากชื่อ action เท่านั้น การคลาย rear lock เพื่อปรับชุดยึดนับ REPAIR ส่วนคลาย spinner เพื่อเปิดทางนับ ACCESS ให้ใช้เหมือนกันทุกคน

### 10.1 ขั้นต่ำต่อ event

```
timestamp, seq, run_id, participant_id (หรือ join ผ่าน run metadata), phase, task_id,
event, action_type, action_id, attempt_id,
target_id, source, input_source, result, reason,
task_state, state_before, state_after,
feedback_id, feedback_visible_at,
content_id, section_id, format, language,
content_version, build_id, test_data
```

ไม่จำเป็นต้องเปลี่ยน schema ของ writer ทุก field สามารถวางใน payload ที่ระบุชัดและ versioned ได้ ห้ามเปลี่ยน API เดิมโดยไม่ตาม callers ถ้า event ไม่เกี่ยวกับ field ใดให้ null ไม่แต่งค่า

- ทุก instance มี authored ID เสถียร เช่น A.ram.M01, A.slot.A2, A.ssd.S02, A.gpu.G01, B.rear_guard_lock
- before/after ของ task-changing event ต้องเป็น full state หรือ initial state+delta ที่ reconstruct ได้โดยทดสอบ round-trip; อย่าเรียก snapshot ชิ้นเดียวว่า state ทั้งเครื่อง
- `source=System` ใช้กับ auto latch/final alignment/animation เพื่อไม่เพิ่มจำนวน actions ของคน
- หนึ่ง effort ที่ต่อเนื่องมี attempt_id เดียวและ begin/end; heartbeat/block ทุกเฟรมไม่เป็นหลาย error ตัวใหม่เริ่มเมื่อ release/ออกจาก interaction แล้วเริ่มใหม่อย่างตั้งใจ ไม่ debounce ทิ้งความพยายามซ้ำจริง
- record source of choice และ displayed info ไม่อนุมาน ‘strategy=Japanese/Thai’ หรือ skill labels ใน runtime
- ลำดับใช้ seq ภายใน run เมื่อ timestamps เสมอกัน บันทึกหน่วยเมตร/วินาทีและ quaternion convention

### 10.2 State A

snapshot มี baseInstalled, mainsIsolated, caseYaw, ทุก slot occupancy และสถานะสลัก, ทุก RAM capacity/type/location; SSD id/capacity/TBW/seat/fastener/data endpoint/power endpoint; GPU id/VRAM/declared power/slot/seat/bracket/power; pending attempts และ system integrity

`installed`, `removed`, `connected`, `incorrectly_placed` ต้องสืบกลับจาก state ไม่สร้างผิดเพราะไม่มีการหยิบชิ้น base ที่เตรียมไว้; incorrect condition ในดิบไม่เป็น ‘คนรู้ว่าตนผิด’

### 10.3 State B

base_stable, mainsIsolated, motorRunning; front_guard_position/alignment/clip; blade_id/seat/pin_alignment; spinner_presence/engagement/tightness; rear_guard_position/alignment; rear_lock_presence/engagement/tightness; observation_accessible_targets; original_fault_active, user_created_issues; visible_feedback

## 11. H1–H4 และตัวแปรวิเคราะห์ที่ล็อก

สี่ข้อนี้เป็นกลุ่มคำถามย่อยตามอีเมล Prof. Fukuchi ไม่แทนเลขสมมติฐานเดิมใน proposal โดยเงียบ ๆ

| หมวด | นิยามและผลสรุป |
|---|---|
| H1 | เวลา reference เปิดโดยผู้ใช้ครั้งแรกเทียบกับ first physical task action (GRAB ของชิ้นงาน/เครื่องมือ หรือ attempt operation ที่เกิดก่อน); Examine ไม่รวมในตัวหาร physical action แต่เก็บเวลาและ first_information_channel แยก; ห้ามสรุป action-first ว่าไม่มีการหาข้อมูลเลย |
| H1 exposure | union ของช่วงสื่อแสดงจริงก่อน first physical action ตัดช่วงค้างที่ข้าม action และหักพัก ไม่บวกซ้อนจากสองหน้าต่าง; ไม่มี action ให้ no_action_observed |
| H2 A | จำนวน distinct targets ของ EXAMINE, ลำดับ, switches ก่อน first assembly attempt; นับความพยายาม INSTALL/CONNECT/FASTEN ไม่เฉพาะที่ทำสำเร็จ |
| H2 B | ตัวเดียวกันก่อน first corrective operation ตามรายการใน §10; ACCESS ไม่ใช่ repair; ไม่มี repair ให้ no_repair_observed และรายงาน exploration observed จนจบแยก |
| H3 | full state ณ first Inspect; n_inspect; meaningful actions และ state changes ระหว่าง Inspect; adjacency Action→Inspect เทียบ Action→Action โดยไม่ข้าม INFORMATION/EXAMINE มาต่อให้ดูติดกัน |
| H4 | จาก INSPECT_FEEDBACK_VISIBLE ผล Fail ไป first meaningful user event: INFORMATION/EXAMINE/ACTION/REPAIR/INSPECT_AGAIN/NONE_BEFORE_END; ไม่รวม Continue/pause/system closures |
| H4 repeat | เทียบ action_type+target กับการกระทำเปลี่ยน task ครั้งล่าสุดก่อน Inspect นั้น เก็บ same action+same target / changed action same target / changed target; ไม่มี previous action ให้ no_prior_action |
| H4 context | incomplete assembly/precondition, specification mismatch, original fault unresolved, user-created issue บันทึกแยก ไม่ถือว่า Fail ทุกครั้งคือซ่อมแล้วล้มเหลว |

หาก Inspect Fail แต่ feedback ไม่แสดงเพราะ error ไม่มี H4 exposure; ไม่มี Fail ใช้ no_failure_opportunity ไม่ใส่ response=0/none แล้วรวมกับผู้ที่ไม่ทำต่อหลัง Fail

### 11.1 ผลการทำงานตาม proposal

- เวลา: task wall duration และ active duration; completion time รายงานสำหรับ Pass เท่านั้น คนหมดเวลาถือข้อมูลยังไม่เสร็จ (right-censored หากใช้โมเดลเวลา) ไม่แทนด้วย completion=420
- Errors: wrong-tool application หรือ deliberate invalid component operation ตาม rulebook; จับมาดูไม่ใช่ error, ‘ไม่เปิดคู่มือ’ไม่ใช่ error
- Wrong requirement: commit การติดตั้งชิ้นที่ไม่ตรง W2 เป็น requirement error ที่ระบุไว้ ไม่ double count ซ้ำที่ Inspect จนมีความพยายามใหม่
- ลำดับต่างจากคลิปแต่ถูกต้องไม่เป็น error; การจัดระบบที่เป็นไปได้แต่ไม่ตรง W2 แยกจาก physical impossibility
- Inspect Fail แยกจาก action errors; retries = Inspect เพิ่มเติมหลัง first Inspect Fail ภายใน task รวมการตรวจครั้งที่ผ่านด้วย; first Fail ไม่เพิ่ม error count อัตโนมัติ
- blocked pair ที่ไม่มีข้อพิสูจน์/implement ไม่ครบ เป็น untested/system issue ไม่เป็น user error

### 11.2 ข้อมูลพฤติกรรมรองที่ไม่เพิ่มงานผู้เข้าร่วม

- first format, openings, visible duration, switches/returns แยก format และ content section
- targets compared ก่อน install; สิ่งที่เลือกเปลี่ยนหลังเปิดข้อมูล; latency ถึง first Inspect
- full state changes หลัง Fail; จำนวนการถอด–ติดตั้งกลับ; สถานะที่ไม่เปลี่ยนแม้พยายามซ้ำ
- time-to-recovery หลัง Fail จน next Pass; ถ้าไม่ผ่านให้ censored ไม่บันทึกว่ากู้คืนสำเร็จ
- evidence coverage เป็น metadata การเข้าถึง ไม่เป็นคะแนนความฉลาด ไม่สรุป causality จาก information→choice

## 12. Movement และวิดีโอ

เก็บ head/controller ทั้งซ้ายขวาเป็นตำแหน่งและ rotation จาก provider จริง พร้อม timestamp, tracking_valid, sample_time/age, input_source, origin และ frame/run IDs; visual hand กับระบบจัดแนวเป็นคนละ stream ไม่แทนข้อมูล provider หัวไม่ใช่ eye gaze

เริ่มจาก sampling ที่ logger/config ปัจจุบันรองรับ วัด actual Hz และ gaps บน Quest ไม่เปลี่ยนให้สูงเพียงเพื่อให้ข้อมูลดูมาก แปลงค่าได้เมื่อความถี่และ valid coverage รองรับ

สูตรพื้นฐาน: ระยะทางเป็นผลรวมระหว่าง valid samples ที่ต่อเนื่อง; speed = distance/actual dt; rotation ใช้ quaternion shortest angular difference; ไม่เชื่อมข้าม tracking loss, teleport, recenter, paused interval หรือ gap>0.25s โดยไม่แยก segment; รายงาน valid time/total active time ทุก stream

เกณฑ์หยุดแบบ operational สำหรับ S1 analysis: speed<0.02m/s และ angular speed<10deg/s ต่อเนื่อง≥0.5s, ต่ออุปกรณ์, ใช้หน้าต่าง median 0.15s สำหรับ derived signal เท่านั้น เก็บ raw ไม่ smooth ทับ นี่เป็นเกณฑ์คำนวณที่เสนอ ไม่ใช่เกณฑ์ยืนยัน ‘ลังเล’; report sensitivity 0.01/0.03m/s แบบกำหนดไว้ล่วงหน้า ไม่เลือกเกณฑ์ที่ให้ p ต่ำ

การกลับมาใกล้เป้าหมาย: controller เข้าในระยะ0.15mจาก target bounds หลังออกเกิน0.20m≥0.5s; target และ bounds ต้องบันทึกสอดคล้องตำแหน่งชิ้นงานที่หมุนได้ ไม่เรียกจำนวนนี้ว่าการตรวจหรือ repair โดยตรง

วิดีโอ FPV ตาม consent ที่มีอยู่ ความละเอียดเป้าหมาย720pตามสไลด์พร้อมtimebaseสอดคล้องlog ไม่สร้างไฟล์วิดีโอว่างปลอมว่าบันทึกแล้ว การไม่ยินยอมวิดีโอไม่ทำให้ event ทั้งหมดใช้ไม่ได้ ประเมินแต่ละ metric ตามข้อมูลที่ยังมีจริง

## 13. เนื้อหาข้อมูลอ้างอิงที่ต้องผลิต

ใช้เนื้อหากลาง S1 เดียวกันสร้างทุก format ภาษาไทย/ญี่ปุ่น การแปลให้ผู้ตรวจภาษาตรวจความหมาย ตัวเลข ปุ่ม feedback และคำว่า ‘อย่างน้อย/ไม่เกิน/จำนวน’ ห้ามถือว่าการแปลจาก AI เป็น human review แล้ว

**A sections:** W2 requirements (ตาราง §5.3) / part specifications / motherboard slots / RAM installation / SSD seating and two connections / GPU mounting and power / inspection meanings.

**B sections:** reported symptom / three possible assembly causes / normal-vs-abnormal observations / safe access / correction per cause / reassembly / inspection meanings.

- PDF ไม่ต้องเป็นคู่มือโรงงานยาวทั้งหมดของจริง ใช้หน้าอ้างอิงเฉพาะงานที่มีสาระครบและอ่านง่าย
- Steps ของ A แสดงข้อกำหนดและขั้นตอนย่อยแยกหมวด ไม่กำหนด order RAM→SSD→GPU เป็นคำตอบเพียงแบบเดียว
- Steps ของ B เป็นเงื่อนไขตรวจแล้วเลือกแก้ ไม่เปิดหน้าตรง fault โดยอัตโนมัติ
- Images แสดงภาพจากโมเดลจริงใน configuration ตัวอย่าง พร้อมคำสั้น ๆ ไม่ใช้ image generation แทนหลักฐานกลไก
- Video เป็นคลิปจริงจากต้นแบบ/โมเดล แบ่งchapterสั้น เล่น/หยุด/seekได้ ทุกchapterรวมมีข้อมูลครบ; ไม่ทำvideo progressปลอม และไม่ต้องให้ดูทั้งชุดเพื่อเล่นได้
- ทุกformatเริ่มที่สารบัญหรือหน้ารวมเดียวกันในระดับเนื้อหา ไม่เปิดตารางคำตอบเฉพาะตัวเลือกที่คนถือ
- ค้นหัวข้อโดยเจตนาได้และย้อนกลับได้ ไม่ซ่อนคำตอบไว้คนละสื่อเพื่อบังคับสลับ
- ข้อกำหนดตัวเลข W2 ไม่ขึ้นบนโจทย์หลักแต่มีครบในทุกสื่อ นี่เป็นการจัดข้อมูลเพื่อทดสอบการเข้าถึง ไม่ใช่ software gate

## 17. การตรวจรับแบบก่อนใช้งานคน — ต้องแยก gate

### 17.1 Rule/data gate (ข้อมูลสังเคราะห์ ไม่ใช่ผลวิจัย)

- enumerating choices ต้องพบconfigurationเชิงสเปกเดียว: M01+M02 / S02 / G01 (RAM2ตำแหน่งสลับได้)
- largest-number shortcut, pile-all shortcut, unconnected-but-present shortcut ต้องไม่Passด้วยกฎผิด
- ยอมรับทุกorderของสามระบบเมื่อไม่ชนทางกายภาพ; A1/B1, G02, S01ต้องfitได้แล้วrequirementไม่ผ่าน ไม่ถูกเด้งออกเพราะwrongID
- ติดตั้ง/ถอด/ยกเลิก/พัก/กลับมาต้องให้stateและlogตรง ไม่setboolpassedเอง
- B openingaccessไม่แก้fault; ringseatedlooseไม่tight; threadedpartยังรั้งก่อนถอดตามกลไก
- B directcorrectrepairและwholecorrectreassemblyผ่านได้แม้ไม่เคยExamine; ไม่เพิ่มfaultลับ
- initialInspect incompleteไม่เท่ากับpostrepairFail; splitcontextในderivedoutput
- codeที่renderfeedbackต้องส่งvisible timestampจริง ไม่ถือว่าbackendcallคือเห็นแล้ว
- ทดสอบข้อมูลก่อนaction: open5s→action20s→close35s ต้องได้15s ไม่30s
- ทดสอบไม่มีinfo/ไม่มีaction/ไม่มีrepair/ไม่มีFail/timeout; ค่าmissingไม่สร้าง0ปลอม
- replayจากไฟล์ปิดแล้วคืนทุกtrackedcomponent stateที่Inspectได้ตรง; ผู้ตรวจดูrawกับวิดีโอช่วงเดียวกันตรวจได้

### 17.2 Device/usability gate

- input/grabเหมือนTraining, no accidental SSD grab when cableselected, no stale tracking asvalid
- พื้นที่ประกอบและทิศหัวต่อมองเห็นได้บนQuestจริงโดยไม่ต้องzoomเกินระบบที่ให้; ไม่มีglyphหาย
- ชิ้นที่ใช้ไม่ทะลุสิ่งกีดขวางทั้งinside/outsidecapturezone และการหมุนเคสไม่พาร่างกาย/โลกหมุน
- ทดสอบsceneครบทุกตัวเลือก โหลดสื่อพร้อมloggingและvideoเมื่อมีconsentตรวจappCPU/GPU/framepacingจริง ไม่เอาEditor65checksเป็นQuestผ่าน
- ตรวจอย่างน้อยramwrong/ssdwrong/partial/missingpower/fanloose/pause/logexportครบ โดยไม่เรียกbuild/installก่อนผู้ใช้อนุญาต

### 17.3 ความยากและเวลารอบนำร่อง

เริ่มทดสอบโดยทีมพัฒนาเพื่อแก้บั๊กได้; การทดสอบกับผู้ไม่รู้คำตอบใช้เฉพาะขอบเขตและจำนวนที่อนุญาตแล้ว ไม่ดึงคนหลักมาเห็นคำตอบล่วงหน้าแล้วนับเป็นnaive

เกณฑ์วิศวกรรมเสนอสำหรับรอบเล็ก4คนที่ผ่านTrainingและครอบคลุมสองสาย (ถ้าอนุญาต): อย่างน้อย3/4ทำสำเร็จต่อtaskภายใน420sโดยไม่มีtask hints และทุกคนเข้าถึงข้อมูล/กลไกได้ ไม่มีcriticalblock. นี่ไม่ใช่เกณฑ์ที่ยืนยันกำลังทางสถิติหรือความยากของประชากร

ถ้าทุกคนเร็วมากให้ตรวจว่าเกิดleak/snapauto/requirementsไม่ได้ใช้หรือไม่ ไม่เพิ่มdelayหรืองานบังคับเพราะคนเก่ง หากทุกคนช้าให้แยกreading/control/access/technicaltimeก่อนแก้UIหรือกลไก ห้ามเปลี่ยนข้อกำหนดเพื่อให้pหรือfailure rateตรงความหวัง

เมื่อเกณฑ์ไม่ผ่าน รายงานว่า S1 ยังไม่พร้อมเก็บหลักและระบุบล็อก ไม่เปลี่ยนfault/เพิ่มhintโดยเงียบ ๆ หลีกเลี่ยงคำว่า‘ไม่ง่ายไม่ยากแน่นอน’ก่อนมีข้อมูล

## 18. ตีความประโยชน์และคำว่า state of the art
