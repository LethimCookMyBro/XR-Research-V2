## ผลกระทบต่อ Protocol ถ้าคงแบบปัจจุบัน
- เวลาวิดีโอเทียบเพดาน 420 s: A ไทย 4:19 (62%), A ญี่ปุ่น 5:46 (82%), B ไทย 3:39 (52%), B ญี่ปุ่น 5:07 (73%) ผู้ที่ดูวิดีโอจนจบก่อนลงมือ โดยเฉพาะฝั่งญี่ปุ่น มีโอกาสหมดเวลาสูงกว่า แม้ทำงานพร้อมฟังได้ (ทดสอบแล้วใน Editor 8 พ.ย.)
- สัดส่วนคนหมดเวลาอาจสูงกว่าที่ Proposal คาด ทำให้ completion time มีข้อมูล censored มากขึ้น ต้องใช้การวิเคราะห์เวลาแบบรองรับ censoring ตามที่สเปก §11.1 ระบุไว้แล้ว
- เอกสารจริยธรรม/ใบชี้แจงผู้เข้าร่วมที่อ้าง 75 นาที ต้องปรับให้ตรงเวลาจริง (สั้นลง) หรือคงไว้เป็นเวลาสูงสุดที่จองไว้

## ผลกระทบถ้าเปลี่ยนตาม Proposal (960 / 1200 s)
- ต้องเป็น protocol version ใหม่ (`task_time_limit` ใน session + export) ห้ามรวมข้อมูลกับ session 420 s
- ต้องทดสอบทาง timeout ใหม่ทั้งสอง task และทบทวนเกณฑ์นำร่อง §17.3 (3/4 สำเร็จภายในเพดาน)
- งานของ S1 ถูกออกแบบให้สั้นกว่า Proposal (ขอบเขตเล็กลงตั้งแต่ 10 ต.ค.) เพดานยาวอาจทำให้แทบไม่มีใครหมดเวลา ความต่างระหว่างแบบข้อมูลจะไปอยู่ที่เวลาทำเสร็จแทนอัตราสำเร็จ
- เวลาทั้ง session จะยาวขึ้นได้ถึงราว 50–60 นาทีในกรณีช้าสุด

## ทางเลือกให้อาจารย์ตัดสิน
1. คงเพดาน 420 s และแก้ Proposal/เอกสารจริยธรรมให้ตรง S1 (ต้องแจ้งคณะกรรมการตามขั้นตอน)
